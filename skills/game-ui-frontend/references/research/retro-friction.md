# What survives a failed attempt?

Snoman Gaming’s critique of some NES games asks two design questions. Could the player see the challenge coming? After failure, which parts did they have to repeat? These questions also belong in an expressive website where someone is filling in an application, configuring a product or reserving a place. The examples below pair decoded footage with selected passages of the original narration, reviewed on 2026-11-20. The judgements about difficulty are the reviewer’s. [Bad Game Design – (Some) NES Games](https://www.youtube.com/watch?v=r1zhhd-JrqA)

| Evidence in the video | Decision for the website |
| --- | --- |
| **Super Mario Bros. 3.** The footage shows a game-over menu and then platforming. In the discussion of the last world, the reviewer distinguishes cleared vehicles and the shortcut after the fortress from two stages he tired of repeating. He describes using save states to skip those repeat runs. The pictured menu includes save options particular to the capture. [Game over, 05:35](https://www.youtube.com/watch?v=r1zhhd-JrqA&t=335s) · [Fortress and save states, 05:57](https://www.youtube.com/watch?v=r1zhhd-JrqA&t=357s) | Preserve the unit of work the visitor has already finished. If one portfolio upload fails, keep the accepted uploads, their order, captions and entered contact details. Offer a retry beside the affected file. |
| **Ghosts ’n Goblins.** In graveyard footage, enemies occupy the upper path as the player jumps. The narration criticises how suddenly zombies emerge and how little warning a player gets. The crowded ground and moving characters are visible. Randomness is the narrator’s account of playing. [Graveyard, 06:47–06:53](https://www.youtube.com/watch?v=r1zhhd-JrqA&t=407s) | Put a consequential condition where a visitor can act on it. Show the accepted format and size at the file chooser. If a file fails, identify it, say which condition failed, and give the visitor a way to replace it. Details about the jury or previous entrants can wait behind a link. |
| **Shovel Knight.** At 08:49 the knight stands on open ground. At 08:50 a flying opponent is visible ahead and above. The narrator praises advance cues and encounters that let the player learn an enemy’s behaviour in a forgiving setting. The sequence gives the viewer room to read both figures. [First encounter, 08:49](https://www.youtube.com/watch?v=r1zhhd-JrqA&t=529s) · [Discussion of cues, 08:58](https://www.youtube.com/watch?v=r1zhhd-JrqA&t=538s) | Give an unusual interaction a low-cost first use. An artist can arrange a submission preview and move an image back before committing. Show the consequence of the final action in its label and put editing controls beside the preview. |

**Worked proposal.** An independent print festival asks for an open-call application that feels like its posters. Stack the artist’s submitted prints into a large, off-register proof. Selecting a print brings it forward and exposes its caption and replace control. Name and contact fields stay on a stable baseline beside the artwork. Show the deadline and actual submission requirements before the first upload. If the last file fails, leave the assembled proof in view, explain the file error in text, and return keyboard focus to the correction when appropriate. After a successful submission, show the confirmation in the same composition. A static proof gives the reduced-motion version the same character.

Try the failure path while art-directing the flow. Can the applicant replace one file, return from detail, and submit the same assembled entry? Those actions reveal whether the visual sequence respects the time already invested.
